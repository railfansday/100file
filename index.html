How Revolut Cut Its AI Coding Bill 90% by Self-Hosting an Open-Weight Model

When British fintech Revolut rolled out AI coding assistants to roughly 2,000 engineers, the bill did what AI bills always do: it exploded. Some engineers were spending $1,000 — even $10,000 — a month on AI tokens with little measurable return.

So Revolut did something almost no company of its size has tried: it ditched the frontier APIs as its default and moved its engineers onto a self-hosted, open-weight model. The result, per Revolut's own numbers, was a roughly 90% cut in AI coding inference costs — plus coding that got about 60% faster.

Not Every Slow Query Needs a New Index

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

What a SQL review taught me about assumptions, AI-written queries, and common-sense tuning

A development team asked me to review the SQL behind a change-data publishing job before they moved it from once a day to once an hour. In QA, one full run took 10 to 12 minutes. After the review, the same run took under 30 seconds. In production, most of its queries now finish in under a millisecond.

Almost none of that came from adding indexes. It came from reading the queries, asking what the job actually needed, and checking each assumption against real data. This post walks through what we found, in the order we found it, and what I would tell any team (or any AI assistant) writing SQL against a busy production database.

The job polls a PostgreSQL read replica for rows that changed since its last run and publishes them as events. It is a classic checkpoint pattern:

I'll use a generic schema for the examples:

Every table has created_at and updated_at. The source system also maintains updated_at_num, a numeric YYYYMMDDHHMISS copy of updated_at, and that column is indexed on every table. Keep that last detail in mind.

Every change-window filter in the job looked like this:

The intent is reasonable: if a row was never updated, fall back to its creation time. But PostgreSQL can only use a B-tree index when the predicate matches the indexed expression. Wrap the column in COALESCE, and the index on updated_at (or updated_at_num) is no longer a candidate. Every window query became a sequential scan of the whole table.

The COALESCE also encoded an assumption: that updated_at can be null. So before changing anything, we checked:

Zero on every table. The source system sets both timestamps when a row is created, so the fallback could never fire. The fix was to drop the function and filter on the indexed column directly:

That one change turned every window query into an index range scan.

The COALESCE wasn't the only defensive habit. One query filtered on TRIM(a.account_type) = 'STAFF'. In QA that is harmless: small tables, fast scans, correct results. In production it does two quiet things:

No padded values, so the TRIM came out, and the queries became consistent with each other.

I want to be clear about where this comes from. The developers I work with write good SQL. But we are now in an era where a lot of SQL is drafted by AI assistants, and they are very good at producing queries that return the right answer. They are much less good at knowing your data. A model will happily add COALESCE, TRIM, LOWER or DISTINCT "just in case", because in the abstract each one is safer. On a 10,000-row QA table you'll never notice. On a 10-million-row production table, each one can turn an index lookup into a full scan.

The result being correct does not mean the assumptions behind it are. Before a query ships, check it against the data's real shape: null counts, value distributions, duplicates, and how skewed the busiest keys are. Or ask a database engineer to review it. It never hurts.

The partner-count query looked like this:

The outer query was narrowed to one organization and a one-hour window: 59 candidate rows. The subquery wasn't narrowed at all. PostgreSQL read 1.77 million membership rows, built a distinct list of 831 IDs, then matched that list against the 59 candidates. That was 31,395 buffers and 83 ms to return a count of zero.

A note on IN versus EXISTS: PostgreSQL already turns IN (subquery) into a semi-join, so the two often plan the same way. The DISTINCT adds nothing, since a semi-join never returns a row twice, and it can push the planner toward building the full list first. Switching to EXISTS helps. The bigger win is adding the filter. If the outer query is limited to something you also know about the subquery's rows, say so in the subquery too. Don't rely on the planner to infer it.

The slowest query in the job didn't return any data. It computed the run's ceiling:

It took 853 ms and about 1 million buffers to return one number. The plan showed three different behaviours:

PostgreSQL has a neat shortcut here. As the CREATE AGGREGATE documentation explains, a MIN- or MAX-like aggregate can be answered from an index, because SELECT max(col) FROM tab is equivalent to SELECT col FROM tab ORDER BY col DESC LIMIT 1. The planner walks the index backward and takes the first non-null value. It also works on partitioned tables and UNION ALL views, by merging each child's index. It does not work through a join. The planner source (planagg.c) limits the shortcut to queries that reference exactly one table, so the join branch had to build the whole join just to find its largest value.

That is where understanding the use case matters more than tuning. This value is an upper bound for the next change window. It doesn't have to be the exact newest staff row; it only has to be at least as high. Dropping the join and taking max(updated_at_num) over all of staff_links gives a bound that is never lower, and costs a single index probe. The join filter still applies in the query that reads the window.

The same review turned up a second easy win. The ceiling was global, but the job ran it once per scope, inside a loop, so it returned the same value several times per run. Computing it once per run cost nothing to change.

The password_changed_at branch I left alone. More on that in Lesson 6.

My first round of EXPLAIN ANALYZE used a one-hour window, the job's steady state. Most queries looked great: under a millisecond. Then I noticed how often the plans said (never executed). In that hour, no organization had changed, so every join after the first step was skipped. The plan was cheap because there was no work, not because the work was cheap.

Widening the window to 30 days told a different story. One query that ran in 0.7 ms on the hourly window chose a completely different plan:

The cause was a row estimate. The planner expected 188 primary memberships and got 15,368, about 80 times more. With 188, starting from memberships looks cheap. A likely reason is how PostgreSQL combines filters: by default it multiplies each condition's selectivity as if they were independent, so correlated filters (type, deleted flag, end date) can be badly underestimated. Check that statistics are fresh with ANALYZE first. If the columns really are correlated, CREATE STATISTICS can tell the planner how they relate.

So I now test every change-data query with three windows:

The first run is easy to forget. Here it was fine: page one of the full-history query took about 20 ms, because the planner could stop as soon as it had 500 rows. But you only know that by running it.

After the rewrites, I had a list of index candidates that would have made every remaining query near-instant: one on password_changed_at, a partial index for a rare account type, and a few more. Before building any of them, I added up what an hourly run actually cost without them:

The slowest single statement was under a second, far from any timeout. Every index you add costs writes, storage and maintenance forever, and here the database was a replication target that would pay for each one on every write. So most of the candidates were dropped. That is a fine outcome. Not every slow-looking query needs an index; sometimes it needs nothing.

One query was different, because its cost multiplied. It loaded full account details in chunks of 100 IDs, and each chunk joined org_members on account_id, a column with no index. Every chunk scanned a 9-million-row table: about 0.7 s.

That is the test I use now: don't ask whether a query is slow, ask whether its cost grows with the data or the backlog. Fixed costs can usually be tolerated. Costs that multiply need an index. We added exactly one: org_members (account_id).

The new index worked exactly as planned: the org_members step went from scanning 5.4 million rows to reading 2,217 buffers. Then I looked at the total for the chunk query. It had gone from 723 ms to 26.9 seconds.

With org_members suddenly cheap, the planner switched to a nested loop and probed memberships once per organization row through an index on org_id. That index holds every membership in the organization, one per member account. The accounts in this chunk belonged to very large organizations, so each probe walked about 14,000 entries to find the one primary membership it needed.

The planner expected roughly one row per probe. When it knows a value in advance, PostgreSQL can look it up in its most-common-values statistics. Here each probe's value came from the outer row at run time, so the planner estimated an average number of rows per organization. The handful of very large organizations didn't fit that average, and re-running ANALYZE doesn't change how the estimate is made.

The fix was another index, but a very small one: a partial index containing only the rows the query asks for.

It holds about 15,000 rows instead of 650,000, so it is small and cheap to maintain, and each probe now lands directly on the row it needs. PostgreSQL uses a partial index only when it can prove, at planning time, that the query's WHERE clause implies the index predicate. The docs point out that a bind parameter such as membership_type = $1 can't prove that. Because this query uses membership_type = 'PRIMARY' AND is_deleted = false as literal values, the planner can match the partial index without any code change.

The lesson isn't "avoid indexes". It's that an index changes the plan around it, not just the step it targets. Re-run the full EXPLAIN ANALYZE after every index, and read the total, not just the line you were fixing.

Both indexes went in with CREATE INDEX CONCURRENTLY, so writes kept flowing. A few things I check every time:

1. Look for old transactions first. Per the CREATE INDEX docs, a concurrent build waits before each table scan for transactions that have modified the table, and after the second scan for any transaction holding a snapshot older than that scan. My pre-check found 65 sessions from a replication tool sitting idle in transaction for 28 days. Before cancelling anything, check whether they actually matter:

Ours held no snapshot, no transaction ID and no locks on the target tables, so they couldn't block the build or hold back vacuum. That's a cleanup item, not a blocker.

2. Run with autocommit on. CREATE INDEX CONCURRENTLY cannot run inside a transaction block, and some SQL clients wrap scripts in one.

3. Decide on lock_timeout deliberately. It lets a build fail fast instead of queueing behind a long transaction, but a build that fails partway leaves an invalid index behind. I left it unset and watched the progress view instead.

4. Check for invalid indexes afterwards. CREATE INDEX ... IF NOT EXISTS sees an invalid leftover's name and skips it with only a NOTICE. Drop it with DROP INDEX CONCURRENTLY and build again, or rebuild it with REINDEX INDEX CONCURRENTLY.

5. Build smallest to largest, and watch replication lag during the big ones.

This is what I now run through for any SQL headed to a large production table, whether a person or an AI wrote it.

Looking back, the biggest gains came from questions, not configuration:

None of that needed database expertise the developers couldn't learn. It needed someone to explain how the planner reads a predicate, why a function hides an index, and why QA data isn't evidence for production. Once that was clear, the developer rewrote the queries himself, and the run time in QA went from 30–50 minutes to under 30 seconds.

Some tuning really is just common sense and basic troubleshooting: read the plan, check the data, and ask what the query is for. If your team writes SQL, especially with an AI assistant drafting it, get a database engineer to look at it before it meets production data. It never hurts, and sometimes it saves you an hour-long first run, or a 27-second query you didn't know you had.

Pricing freelance dev work: from hourly rate to a project quote

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

If you freelance as a developer, you'll probably be asked for an hourly rate, a sprint price, a monthly retainer and a fixed project quote, sometimes all from the same client. They can all come from one number. This post builds that number from your own costs, then turns it into each kind of price, with a short section on keeping scope creep from eating the margin.

All dollar amounts, hours and percentages below are made-up example figures, picked so the math is easy to follow. They aren't typical, average or recommended rates. Swap in your own. Tax and buffer percentages here are planning aids, not tax or accounting advice.

Start with what you want to take home in a year, then add what the business costs to run. For a developer that might be a hardware replacement fund, IDE and SaaS licences, hosting and domains for your own projects, insurance and accounting.

Example: take-home goal $67,200, plus expenses of $400/month × 12 = $4,800, so $72,000 in total.

Part of each invoice may need to go to tax, and a buffer can help with slow months and gaps between contracts.

Example: 25% tax set-aside + 15% buffer = 40%, which leaves 60% for income and expenses:

$72,000 ÷ 0.60 = $120,000 revenue needed (example figure)

Some of a freelancer's week probably can't be billed: sales calls, proposals, invoicing, keeping your own tooling up to date, learning a new framework for the next contract. Holidays and sick days come out too.

Example: 35 working hours a week, 10 of them non-billable, so 25 billable hours × 48 working weeks = 1,200 billable hours a year.

$120,000 ÷ 1,200 = $100 an hour (example figure)

That's your floor, not a target. Every other price below starts from it.

Some clients, especially teams already running Scrum, may find a per-sprint price easier to budget than an hourly one. Multiply the billable hours you'll commit per sprint by your rate.

Example: a 2-week sprint at 25 billable hours a week = 50 hours × $100 = $5,000 per sprint.

Say in writing what a sprint includes (planning, demo, a set number of hours) and what happens if the client adds work mid-sprint. For example, it waits for the next sprint, or it's priced as a change.

After a launch, a client may want someone on call for bugs, dependency updates and small fixes. A monthly retainer turns that into a fixed number of hours at your rate.

Example: 10 hours a month × $100 = $1,000 a month for maintenance.

Some clients may prefer a fixed price for a whole project. Break the work into tasks, estimate each in hours, then add a contingency for the unknowns: the third-party API with thin docs, the legacy code nobody has touched in years.

That's 64 hours. Add a 25% contingency and you get 80 hours × $100 = $8,000 (example figure).

To spread the risk, split payment into a deposit and milestones.

Example: a 25% deposit of $2,000 before work starts, then the remaining $6,000 in three milestone payments of $2,000 each (say, accounts done, API done, launch).

A fixed quote holds up best when the scope does. "Can we also add a CSV export?" sounds small, but a few requests like that can push the hours well past the estimate.

Example: if the $8,000 project ends up taking 100 hours instead of 80, the effective rate drops to $8,000 ÷ 100 = $80 an hour, below the $100 floor from step 3. That can be a signal to tighten scope, raise the contingency, or re-estimate next time.

Pen and paper or a spreadsheet can handle this math. Re-run the numbers whenever your costs, hours or goals change.

Scott "Stew" Stewart debuted a blinding glow-up.

The Love Is Blind star took the internet's advice by growing a beard to enhance his facial features.

"The sweet smell of victory," the 34-year-old captioned a TikTok showing off his suave new stubble, using audio of Michael Scott's famed line in The Office, "Well, well, well, how the turn tables turn."

And viewers were delighted to discover Stew's dapper new facial hair ahead of the season 11 reunion, set to air Nov. 8, after fan pages, hairstylists and med spas circulated images online that reimagined the reality star with a brawny beard to accentuate his jawline while complementing his eyes.

"The beard has arrived," one user wrote, to which Stew responded, “The people have spoken!!!"

And when another fan added, "Keep growing it out trust us," he quipped, "I never doubted you."

Stew is taking any styling tips in stride, responding to a user demanding he grow his beard longer by writing alongside a crying emoji, "Noted for the next one."

Stew's appearance first became a topic of conversation after his fiancé Jacqueline "Jax" Guelli called off their engagement seconds after their first face-to-face meeting despite building a connection behind a wall. When the engineer told Jax that he'd gained a reputation in the pods for resembling a Kennedy, she quipped, "More like Mitt Romney."

But the 31-year-old later clarified that she didn't ghost Stew on a whim despite how it appeared on the show.

"I just lost control of my emotions, and all I knew was to go home," Jax told E! News. "Truly it had nothing to do with him as a person."

She admitted that her cold feet began with the proposal in the pods, adding, "I was like, 'That didn't feel right.'"

Still, Jax moved forward with the relationship, hoping their in-person connection would take her by surprise.

"I wanted it to be like an aha moment, like, 'OK, now all is well. We have real time chemistry and connection,'" she explained. "It just was not there for me. And unfortunately, I panicked and I left."

Since then, the former couple has discussed the mishap "many times," the skincare founder said, including when she sent Stew a DM after leaving the show.

"It was super sincere," Stew told E! News. "She explained that it wasn't about me. It was about just the emotional overload of the previous couple weeks."

Read on for more behind-the-scenes of Love Is Blind, straight from the pod squad.

1. Are contestants paid to be on Love Is Blind? Former star Matthew Duliba said they are paid $5,000 to appear on the pod period of the show.

The real money is made in sponsorships afterward, as season two alums Deepti Vempati and Natalie Lee said they each made about $500,000 as influencers in under two years after their episodes aired in 2022.

2. Where do the cast members sleep while in the pods? According to Netflix, the contestants slept on cot beds in trailers next to the lounges during season one, but for season two they upgraded to hotel rooms to be more comfortable. They're escorted to and from their rooms by staff so they can't secretly see anyone.

"You're actually at a hotel," season four's Micah Lussier shared on TikTok in 2025. "That's where you're staying, and then the pods that you see is a set, so think of a big studio, and then the bathrooms are outside in trailers."

3. The reality stars don't get access to their phones starting in the pods until after they're back from their tropical vacation portion of filming.

Shayne Jansen shared of their vacations, "You don't have your phone or anything on you."

4. The pods portion of the experiment lasts about 10 days, with 40-50 hopeful singles serving as the initial cast. But over the course of the process, some singles are let go.

"There was a certain point where we did a whittling down of people just to focus internally on the people who were really connecting, to allow them more time," Love Is Blind creator Chris Coelen told E! News. "We ended up having maybe 20-25 people in the pods at that point."

5. The first dates between all of the singles were set up speed-dating style rotation, with everyone spending eight to 10 minutes with each person of the opposite sex. From then on, there were no limitations put on who you could talk to, when you could talk to them and for how long, as long as a production intermediary set it up as they were unable to communicate with each other outside of the pods.

6. According to Sal Perez from season two, the singles are given "talking points" and "questions" before heading into their dates, but they don't have to use them.

"There were kind of topics for the day," Kyle Abrams added in an interview with E! News. "It was good if there was a lull in conversation, you just refer to the little notebook and you can drum up conversation."

That being said, the show is far from scripted. As contestant Kelly Chase told Business Insider, "Although it might sound unbelievable (trust me, it was hard to believe myself), the show wasn't scripted for the cast."

7. As for what they eat on set? Kelly said that was one of the aspects of filming she enjoyed most, explaining that contestants are offered a wide range of options while in the pods.

"During the first 10 days of filming," she said, "we could choose from catered food that included options like grilled fish, chicken, steak, vegetables, pasta, rice, and fruit."

8. All the proposals happen on the same day, though some are shown earlier in the episodes to avoid watching them all back-to-back.

“Everyone gets engaged on that one day. And then the next day is the big reveal day," Kelly said, per Cosmo. "And then the couples separate and go back through their own door. You meet them [your partner] for 15 minutes—the person you just got engaged to—and then you don’t see them again for a few days. It’s crazy."

9. Where do the engagement rings come from?

"We supply them with the rings, and at that point, those rings are theirs," the creator told Entertainment Weekly in 2025. "They never have to give them back if things don't work out. They're their rings. And if they want to say that they paid for them, then that's up to them. They can say whatever they want."

10. Hosts Vanessa Lachey and Nick Lachey are no longer allowed to be at the reveals.

"We all used to be at the reveal," Vanessa told Parade in 2025. "So when they would come out on the red carpet, it was me, it was Nick, we had like the glam girls there, we had costume design, we had audio. We had everybody standing there."

But it ended up being "probably 50 people" in the room, which detracted from the romance.

"It got to a point where it got too loud," Vanessa added. "After that, they were like, 'No more people at the reveal. Just the cameras and the couple. This is their moment.'"

11. Hoping to see a few proposals, producers were not expecting more than five couples to get engaged in season one. So when two other couples (in addition to the six the show chose to follow) also ended the pod portion with an engagement, producers ultimately couldn't continue filming their journey.

"We felt like we wanted to tell diverse stories frankly," Coelen reasoned. "We weren't sure where the stories were going to go, everybody felt like they truly found the person they wanted to spend their life with and we had an abundance of story...we just didn't have time in the show to follow them, which is incredible to me."

12. One of those engaged couples was Rory Newbrough, who was often seen giving advice to the other men, and Danielle Drouin. They spent a week together in Miami as the other engaged couples went to Mexico to continue filming. But soon after they returned to Atlanta, they had a "very amicable" breakup when Danielle realized she still had feelings for another cast member, Matt Thomas. "She ended up wanting to pursue that," Rory explained to People. Danielle and Matt ultimately didn't last either.

13. The other unaired season one engagement was between Westley Baer, who was briefly shown discussing dating as a shorter man, and Lexie Skipper. Despite not continuing with the show, they dated for three months back in Atlanta. But Westley revealed to People that his career change caused their split. "I made a crazy decision to sell everything I owned, and I moved to Asia," he said.

Two season two couples—Caitlin McKee and Joey Miller and Kara Williams and Jason Beaumont—also got engaged, but didn't have their journeys filmed.

14. Are constants allowed to talk when there's not cameras around?

"In the pod stage, the answer is no," Micah said. "There's always cameras rolling in those pods. And when you're in the lounge, they don't want people talking if there's not cameras rolling, so it will be quiet on set. And that is because if you're talking about stuff, they can miss part of the storyline."

She said the experience in Mexico is similar.

"You won't fly together, you won't do anything off camera until they leave you alone in that room that first night," she said. "So, that's the first time that you get a talk off-camera."

But when they go home, there's more freedom to speak without being filmed.

"You have scheduled filming days, like every other day," she explained. "So of course, you get a ton of time off camera to get to know each other without them in your face."

"They pay for the dress," Micah said of the production team. "I remember when we went there were some dresses that were included and part of the budget, and we could choose from those. And there's a lot to choose from."

However, they also "had the option" to "upgrade" to a more expensive dress that they paid for. The season four star added, "To my knowledge, no one ever did that."

16. As for who paid for the weddings, a Netflix spokesperson revealed to Women's Health that production "supplies some of the basics, but because these are their real weddings, it's up to them as to how to spend their money." So the couples likely did have to cover some expense if they went over budget.

17. Despite some skepticism from viewers, the marriages are legit, with season one's Lauren Speed telling Refinery29, "This is a real legally binding marriage. This is not for TV. This is our life."

18. It's not random who goes first on the alter saying "I do" or "I don't," with Micah saying the production crew determines who goes first.

"It's not the officiant who decides," Micah revealed. "In my opinion, they will ask whoever they think is more likely to say 'yes' to go first, because then they get a two [person] answer."

Otherwise, she noted, "you don't have that chance of seeing the first person say 'yes' and having that shock."

19. So were the cast members obligated to make it to the altar? According to Coelen, they were not. "They certainly could choose to do whatever they wanted to do," he told E! News of the wedding day decision-making process. "Again, being there on the wedding day, I personally, knowing these people and their stories, I didn't know what was going to happen."

20. Then why do people wait until the altar to decide if they're going to say yes or no? While contestants aren't required to go through with the wedding day, there's a reason many do, even if they ultimately say no.

"In my experience, it wasn't like you have to get to the altar, like you must get to the altar," Micah shared on TikTok. "It was moreso being a part of the entire experience. The whole point of Love Is Blind is It's an experiment. And you wouldn't know if it's going to work or not unless you do the whole thing. So that was the thought process there."

21. Why do so few couples say “I do"? After only one pair of contestants tied the knot in season eight, Love Is Blind executive producer Ally Simpson provided insight into why it’s getting more rare for couples to make it past the altar, admitting that social media has made it challenging to recruit “nice men” for the experiment. She also noted that former contestant Chelsea Griffin joined the casting team to help mitigate the issue.

22. There were rumors online that Mark Cuevas, the youngest single man in the inaugural season, secretly had a girlfriend when he was on the show, which he later denied.

"I did not have a girlfriend the whole time," he said on the Be There in Five podcast. "I was single before [going on the show]. Now, being a single man, you're single, you're doing your thing. I'd never had a girlfriend before. Where was the time to be in a relationship during the experience?"

23. According to Kelly and Kenny Barnes, they never had any plans to actually get married at the end of filming season one. "We were adamant about we're not going to get married," Kenny told People. "And really, the engagement was just to extend the experiment. And we were both committed to that." And Kelly believed they were "going to continue dating, because that was communicated between us." That was until Kenny admitted on the wedding day he was not "emotionally available" to do so. "I felt very rejected," she admitted. "Like, 'That wasn't the plan. What the heck?'"

24. Jessica Batten, LIB season one's most polarizing cast member, claimed in an interview that she tried to quit the show but wasn't allowed to.

"I mean, I had to stay," she told EW. "I definitely had a conversation about leaving and I wasn't able to do that. My dog got sick too, and almost died during the show, I had so much other stuff going on."

She continued, "It was really frustrating because I kind of knew [Mark and I] weren't going to get there. I definitely had some conversations and attempted to leave, but I wasn't able to."

25. The season one weddings were actually filmed in the fall of 2018, meaning the two couples—Lauren and Cameron Hamilton, and Amber Pike and Matt Barnett—who actually decided to get married had to keep their relationships secret for 18 months before the show premiered.

26. Love Is Blind could go on and on for years, with Coelen telling E! News, "I'm thinking season 15" would be the last.

27. Did Carlton Morton look familiar? Well, it's because he's been on an ATL-set reality show before, popping up on The Real Housewives of Atlanta when he was working as Cynthia Bailey's assistant back in 2014. Bravo fans will remember he got into a heated argument with Kenya Moore, who had just joined the series.

28. Why does the show always have those gold cups? While fans have speculated the opaque cups help hide the amount of liquid in the glass to help with editing errors and cuts, Coelen said the goblets were chosen for aesthetics.

"When you turn on the show, you know it's our show," he told Variety. "It's a very authentic, really true following of these people's journeys, but I like the fact that we have this sort of connective tissue with that in a really light way, it's fun."

Deepti added to E! News, "We would always put all of our drinks in the gold goblets. It's just a symbolic thing for us."

Beginner Tips And Tricks In Loftia

📅 Nov 04, 2026  |  Category: World  |  Read Source →

The world of Loftia is all about adorable sustainability, but it can be a little confusing when you first start out. Here are some tips and tricks you might need to get yourself fully immersed in this lighthearted, uplifting world.

Keep in mind that, as of the time of writing, Loftia is in its Early Access and as such does not contain its final features.

When you're just starting out, you don't need to worry too much about the aesthetics of your house. You'll want quick and easy access to your Project and Cooking Stations so that you can make what you need without having to run all the way to some obscure area first. I have my machines right inside my front door, sitting on opposite sides as you come in. This makes it easy to grab and go as I'm playing.

Learn how to get energy, upgrade your battery, and expand your solar farm in this complete energy Loftia guide.

Loftia City is the central hub of the game, full of resources and helpful NPCs you can talk to and get things from. It does, however, require you to jump in a balloon and move to a brand new area, which means waiting on loading screens.

Rather than having to hop back and forth between the city and your neighborhood constantly, try to plan ahead a little bit. Get all of your shopping and resource gathering done in one go as often as you can so that, when you do go back home, you've got everything you need to expand, plant, craft, and decorate for whatever project you're working on at the time.

You can expand your little island in Loftia to match your needs, whether that's giving yourself more room to craft, garden, or decorate. You do this by getting permits from Amani in Loftia City. It's a good idea to start with practical upgrades like a second energy station or garden bed before you focus on the upgrades that will give you more room to play with aesthetics. This lets you progress the game a bit more quickly and efficiently so you're not waiting around forever for things to grow or batteries to recharge.

Navigating Loftia City can be a little confusing at first; it's large, round, and pretty easy to run through blindly during the tutorial when you're looking for a specific NPC or location, meaning you don't get a great sense for the layout until you're exploring on your own later on.

While most of the major locations are marked, a couple of places (like the construction sight) aren't, which can make getting to them to go resource hunting a little more challenging. If you open your map (press M) and then right click, you can place a marker that will help you navigate toward your destination.

Markers will show up separately to your main quest arrows, so you don't have to worry about confusing the two.

As with any resource management game, you'll want to sort out your system for storing your resources and other materials early on. I like to have all of my raw materials in one chest, seeds and/or cooked items in another, crafted items in a different one, etc. You should also keep your chests relatively close to your machines if possible as well — again, having them by the front door is a good move, though you might also store them in front of the door as a part of your decorations.

I keep storage chests for food and seeds next to my Cooking Station, which is near where I laid out my garden beds for maximum convenience. Having a workflow makes life easier, even in gaming.

Cooking in Loftia is pretty easy, but it does involve a little clicker mini-game. You'll need to keep your mixing spoon in an ideal zone on a circle by clicking, not too quickly but not too slowly. If you can do that, you'll cook higher-quality food worth more Dew. If, however, you can't keep up with clicker games for whatever reason, Loftia has included an accessibility feature that turns off the cooking mini-game. I really appreciate this, as some folks may have limited dexterity and still want to enjoy the game; some folks might also just want to play the game in as low-stakes a mode as possible, and that's perfectly valid, too.

You can find the toggle for this by hitting Escape, then the gear for main settings, then tabbing to the Accessibility menu.

If you ever find yourself stuck or unsure what to do next, take a little time to chat with the NPCs around Loftia! Speaking to different characters can unlock additional quests, which gives you more activities to work toward when you're running low on things to do. Many of these quests also come with their own rewards, including new items, cosmetics, and other fun goodies to collect.

Even if you're more interested in decorating your home or dressing up your character than completing every task on your list, it's worth making the rounds and getting to know the locals. You never know what cute reward might be waiting behind a conversation!

Before buying a bunch of seeds, stop by Hazel's Seed Shop and check how much each crop sells for in the top-left corner of the page! The shop provides useful information about the selling prices of different crops, which makes it easier to plan your garden and decide which seeds are worth investing in.

If you're trying to make money efficiently, this is a great way to compare your options before spending your hard-earned resources. A bit of planning now can save you from filling your entire garden with crops that aren't particularly profitable!

Democratic socialist Melat Kiros has won the race to represent Colorado's 1st Congressional District in the House, according to a race call by The Associated Press, marking the first time a Gen Z woman will serve in Congress.

Kiros, a 29-year-old Ethiopian immigrant and lawyer, cruised to victory Tuesday night in the reliably blue district, which includes most of Denver.

The win comes just months after she handily defeated 15-term incumbent Diana DeGette in the state's Democratic primary, a high-profile party upset where voter frustration with leaders in Washington, D.C., and calls for political change were at the forefront.

Kiros is one of several winning House candidates on Tuesday who were endorsed by the Democratic Socialists of America or its local chapters.

They also advocated for more divisive changes, such as abolishing Immigration and Customs Enforcement and ending U.S. military aid to Israel.

Kiros' fierce criticism of Israel and the war in Gaza became a source of controversy on the campaign trail, sparking blowback from the independent candidate in her race, Shimon Blau, who accused her of espousing antisemitic rhetoric. Currently, just one sitting member of Congress is under the age of 30, Florida Democrat Maxwell Frost, who became the first Gen Zer elected to the House in 2022.

Rhode Island Voters Back $120M Bond Measure to Support Affordable Housing

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Rhode Island voters are projected to pass a ballot initiative to support increased housing through a massive bond issuance.

Rhode Island's Question 2 issues $120 million in general-obligation bonds, which could then be used in various costs to increase the supply of affordable housing. The funding would go to pre-development work, new construction, property acquisition, and infrastructure improvements.

At 9 p.m. ET on Tuesday, an hour after polls closed, the measure had 61% support with 84% of the vote reported, according to the state's Board of Elections. The measure needs 50% support to pass.

Of that money, $25 million must go to increasing construction of for-sale homes and $10 million for public housing. The state expects construction on these projects to begin in 2028 and the new housing to come online from 2029 to 2032. That's according to the state's information on the ballot measure, which notes that the total cost of the bond will top out at around $192.5 million with interest.

The National Low Income Housing Coalition estimates that Rhode Island, with a population of about 1.1 million people, is short around 23,000 affordable rental homes for low-income renters. Around 30% the state's renters are considered extremely low income, with an average income of $31,970 for a household of four. According to NLIHC, renters need to make an annual household income of $70,617 to afford a two-bedroom rental home at HUD's Fair Market Rent.

Many prospective buyers in Rhode Island are also being priced out.

Rhode Island's median listing price is $569,900, about $150,000 more than the median national listing price of $419,250.

Housing Works Rhode Island's 2026 Housing Fact Book found that purchasing a home in Rhode Island is out of reach for anyone making the median annual income and that housing costs continue to outpace wages.

Around a third of Rhode Island's homeowners are considered cost-burdened, and spend more than 30% of their income on housing.

In the state's capital city, Providence, less than 4% of homes were considered affordable to middle-income buyers, showing a significant misalignment between available homes and local income level. In fact, Providence ranks among Realtor.com's most misaligned markets when it comes to incomes meeting the cost of housing.

Former Gov. Dan McKee, who made housing reform a major focus of his administration, urged voters to support the bill. In September, he was defeated in the primary by Helena Foulkes, who is running against Republican gubernatorial candidate Aaron Guckian.

Guckian expressed opposition to the measure.

"Before we ask taxpayers to borrow another $120 million, plus interest, I think we owe them an accounting of the housing money we're already spending and what we're getting for it," Guckian wrote in an email to the Providence Journal.

TL;DR: The Hong Kong Monetary Authority and the Hong Kong University of Science and Technology announced a post-quantum cryptography assessment toolkit on November 2. Post-quantum migration is not the same thing as making every blockchain or bank system instantly quantum-secure.

Good security planning is often unglamorous. Discovering where keys are issued, which partners rely on them and when equipment will be replaced is difficult work, but it makes future transitions possible. The banking sector has a reason to start early because data captured today can remain sensitive long after the original connection has ended.

The Hong Kong Monetary Authority and the Hong Kong University of Science and Technology announced a post-quantum cryptography assessment toolkit on November 2. The initiative is aimed at helping banks understand where current cryptographic systems might need upgrades as quantum capabilities develop. It is a preparation programme, not a declaration that quantum computers have broken banking or cryptocurrency encryption. The dated original disclosure is the starting point for the figures and product scope discussed here.

Large organisations use cryptography in certificates, customer authentication, interbank links, software updates and the storage of sensitive data. Migrating those systems can take years because algorithms, devices, vendors and legacy applications must remain interoperable. A toolkit can help identify dependencies, prioritise sensitive data and test readiness for future standards before a forced emergency transition.

The HKMA has pointed to gaps in sector readiness and ambitions to improve preparedness by 2030. The most immediate benefit may be governance: teams can assign ownership of the inventory and agree which systems require the longest lead time. That is more useful than debating a speculative date on which a general-purpose quantum computer could break a particular cryptographic scheme.

A crypto incident produces several separate timelines: containment, investigation, recovery and a return to reliable service. Those phases can overlap without finishing together. A traced wallet is not automatically frozen; a frozen balance is not automatically returned; and a reopened withdrawal route is not a completed security audit. Keeping those differences visible helps readers judge progress more accurately.

For additional perspective, it is worth reading our existing reporting on Binance’s earlier staged withdrawal restart and Bitcoin payment infrastructure and node software context. Those background reports help separate established facts from a new, still-developing announcement.

Post-quantum migration is not the same thing as making every blockchain or bank system instantly quantum-secure. Different primitives face different levels of risk, and some proposed methods affect key size, verification performance or compatibility. The toolkit’s output is an assessment input, not a substitute for independent engineering and formal testing.

Operational controls matter most when a business is under stress. Security announcements should identify the system affected, the customers who can act, the evidence supporting any recovery number and what remains uncertain. Clear scope protects users from false reassurance and from unnecessary panic. It also provides a sensible basis for follow-up accountability.

Watch whether participating institutions publish migration road maps, begin procurement changes and test post-quantum authentication with core systems. For crypto readers, it is a reminder to separate near-term operational security from longer-term cryptographic research. No credible reading of the announcement implies that Bitcoin private keys are currently being routinely cracked by quantum machines.

(London) – Scores of academics and students at public universities in Bangladesh have been arbitrarily punished because of their alleged affiliation with former ruler Sheikh Hasina and her Awami League party, Human Rights Watch said today.

Any action to punish persons for their peaceful beliefs or without ensuring due process would violate the rights to freedom of expression and association protected under international human rights law and reproduce abusive attempts under previous administrations to control political opinion and expression at Bangladesh’s public universities.

“Bangladesh has a long history of political debate in its universities, and only autocrats should fear such discourse, not a government formed following student protests,” said Meenakshi Ganguly, deputy Asia director at Human Rights Watch. “Bangladesh needs to turn the page on the repression of the past, not repeat it whenever the ruling and opposition parties trade places.”

The sanctions—dismissals, suspension, and teaching restrictions—focus on allegations that they were complicit in violence by Hasina’s Awami League government, which was toppled by student-led protests in 2024, allegations of other “subversive” activities in support of her party, or their alleged discrimination against students wearing Islamic clothing. Hundreds of students, allegedly Awami League members and supporters, are also being expelled, denying them their education rights.

Human Rights Watch interviewed over a dozen affected teachers, examined university correspondence, and reviewed and analyzed a televised discussion and a video posted on social media. Interviews with teachers and students also confirmed expulsions, cancellation of exam certificates, or barring students from campus.

According to media reports in August 2026, at least 404 more academics at 22 universities, who were part of a pro-Awami League Telegram messaging app group, have been put under investigation. “What is happening now is that the university authorities are targeting with false allegations the group of teachers who are aligned to the Awami League and did not support the 2024 student movement,” said a professor at a public university, who is not identified for security reasons. “We are not allowed to go take classes, we cannot do research work, we cannot do anything.”

Hundreds of people were killed in a brutal police crackdown on the protests in July and August 2024, which forced Hasina to flee and paved the way for the return of the Bangladesh Nationalist Party to power following an election in February 2026. The activities of the Awami League were criminalized by an interim government in May 2025.

For years, Bangladesh’s universities have been run in a partisan manner, employing and promoting academics close to the party in government and acting against supporters of other political parties.

Starting in September 2024, the newly appointed authorities at Dhaka University, the country’s most prestigious university, ordered 44 academics to stop their work and restricted teaching assignments of another 25, without a transparent or credible disciplinary investigation. Subsequently, six of the academics were formally “temporarily suspended” following the findings of an inquiry committee, and similar investigations have now begun against another 14 teachers.

Another 85 teachers were denied promotions.

In all, over 20 public universities have been affected, Human Rights Watch found.
